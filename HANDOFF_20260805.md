## Approach for the workbook repair

### Phase 1: freeze and inventory

1. Fetch remote `main` and record the exact paper commit used for reconciliation.
2. Hash the original workbook and make a dated backup before changing it.
3. Inventory every sheet's dimensions, formulas, merged cells, hidden rows/columns, freeze panes,
   filters, widths, number formats, conditional formatting, images/charts, and print settings.
4. Save a formula map and a style map. This makes accidental formula replacement or formatting damage
   detectable.
5. Re-run the existing claim-audit extraction against the fetched v4 source so the starting ledger is
   current.

### Phase 2: establish source-of-truth rules

Use this precedence:

1. per-run raw artifacts and locked manifests;
2. checked-in analysis/rollup scripts and their generated CSV/JSON summaries;
3. verified manuscript tables and figures;
4. workbook cells.

The workbook is a reproducibility and presentation layer, not the authority when it disagrees with a
rerunnable result artifact. Every summary row must record:

- exact source path and hash;
- generation command;
- architecture/training/representation;
- generated-tree count;
- eligible-tree count and explicit excluded IDs;
- ordering count under its separate eligibility rule;
- metric definition, aggregation rule, and SE definition;
- whether the source is fresh shared-tree, historical archive, or organic-family evidence.

Do not combine historical and fresh cohorts in one summary range. Do not treat generated `n=50` as
topology-scored `n=46`.

### Phase 3: build a reconciliation ledger before editing

Generate a machine-readable ledger with one row per paper claim/table cell/figure statistic:

| Field | Purpose |
|---|---|
| paper location and quoted claim | identifies the consumer |
| workbook sheet/cell | identifies the current provider |
| raw source artifact | identifies the authority |
| paper value / workbook value / recomputed value | exposes the mismatch |
| sample IDs and `n` | catches cohort drift |
| metric and uncertainty definition | catches semantic drift |
| status | match, stale, sample mismatch, formula bug, label bug, source missing, intentional archive |
| proposed action | update raw input, repair formula, relabel/archive, update paper, or investigate |

Start from the August 3 claim ledger, but extend it to cell-level mappings and current table/figure
labels. Review the ledger before bulk workbook changes.

### Phase 4: repair in dependency order

1. Update `Source Manifest` and `Reproduction Commands` first.
2. Replace or append raw data blocks from current compact CSV/JSON sources. Preserve historical rows
   only in explicitly labeled archive sheets; do not let them feed live paper summaries.
3. Repair formulas and ranges in calculation sheets. Prefer formulas over pasted summary values.
4. Rebuild summary sheets from those formulas:
   - fresh shared-tree recovery/ordering;
   - fresh LayerTrace subsets and the refreshed per-tensor profile metadata;
   - current behavior bridge, heterogeneity, and empty-output sensitivity;
   - current within-task results;
   - fresh three-condition PhyloLM comparison;
   - Figure 2 diagnostics and paired-bootstrap odds ratios.
5. Update `Claim Index`, `Paper Update`, and `README` last, after all downstream values are stable.
6. Decide explicitly how to handle removed material. Recommended default: move the historical PhyloLM

## Claude review triage and author response

Claude rated the paper a 5 and proposed a large set of experiments and reframings. Do not treat that
review as an accepted work plan. The author agrees with a few targeted fixes but rejects several of the
review's premises. The intended response is below, in priority order.

### Highest-priority planned work

#### 1. Restore the existing random baseline and leaf-count stratification in the appendix

The small number of leaves is a fair limitation, and larger-tree experiments will begin, but the paper
should not be reorganized around this issue or lead with it before those experiments are ready. This is
a standard concern that will remain available to reviewers regardless of the tested size.

The immediate response is to restore analyses that have already been run:

- recovery stratified by leaf count;
- matched random-topology recovery by leaf count;
- preferably recovery above the matched null; and
- the number of true splits in each stratum.

Do not repeat Claude's generic ``one in three'' chance statement as if it applies to the full sample.
That value is specific to a four-leaf binary unrooted topology. The appropriate null is matched to each
truth tree's leaf count and split structure.

Continue larger-tree work in parallel. Treat 16- and 32-leaf trees as a research extension, not as a
submission blocker or promised result until completed.

#### 2. Run a depth-adjusted behavioral bridge analysis

The concern that depth may mediate both weight distance and output behavior is fair. Refit the bridge
while controlling for pair-level depth features, such as mean leaf depth, absolute depth difference,
and—if available—shared-ancestor depth.

The author does not accept the claim that immediate EOS is not behavior. Preserve the conceptual
distinction:

- Llama EOS is an observed response behavior on the requested held-out task.
- The degenerate Flan translation cells answer with labels inherited from the last trained task, so the
  translation probe no longer measures translation behavior.

Keep the EOS-inclusive estimate and the empty-excluding sensitivity. The depth-adjusted result should
show whether EOS and shared depth explain the full association rather than redefining EOS as missing or
invalid behavior.

#### 3. Finish the anonymous artifact release

This is easy and high leverage. Release the code, locked manifests, compact per-run summaries,
reproduction commands, and appropriate distance cubes through an anonymous artifact URL. Add the URL
before submission.

### Claims to clarify and defend, not abandon

#### 4. The layer result is sparse sufficiency, not exclusivity

Claude's layer criticism attacks a stronger claim than the paper needs. Other layers performing well
does not invalidate the finding that a small self-attention subset is sufficient.

The intended claim is:

> A small self-attention subset is sufficient to reconstruct lineage across Flan, Llama, and Pythia.

The paper does not need to claim that only self-attention contains lineage signal. Flan's fresh
per-tensor profile is diffuse, but the 12-matrix encoder self-attention key subset still matches the
all-weight reconstruction. Llama and Pythia provide additional evidence that self-attention is a
strong lineage carrier.

Also make the out-of-sample provenance explicit: the Flan `enc_sak` subset was identified using the
historical cohort and then evaluated on the fresh 46-tree cohort. Claude's assertion that selection and
evaluation occurred on the same 46 trees is incorrect.

One terminology fix is reasonable: a subset recovering 93.5% of clades should not be presented as a
failed ``negative control.'' Rename `low_signal` in the prose to a LayerNorm control or historically
low-signal subset without weakening the self-attention sufficiency claim.

#### 5. The diagnostic result remains valid

The author does not accept the claim that the additivity/Atteson result must be rebuilt. The observed
relationship is clear: higher diagnostic values correspond to higher recovery over the displayed
operating range.

The direct rebuttal is:

- Figure 2 contains 400 estimator summaries, not roughly 8--30 points.
- Those summaries are backed by 18,400 paired estimator-tree records.
- Every estimator uses the common 46 topology-eligible tree IDs.
- The paired bootstrap resamples those tree IDs jointly.
- The paper presents additivity and the fitted Atteson margin as empirical diagnostics, not causal
  mechanisms or universal guarantees.

Variation across methods is useful when the estimand is whether a distance-matrix diagnostic indicates
expected reconstruction quality. It would be a confound only for a causal claim about why one method
outperforms another. Clarify the number of estimators, pairing, and diagnostic interpretation if needed;
do not discard the result merely because PhyloLM expands the observed recovery range.

### Scope rebuttals

#### 6. Keep PhyloLM as published

Do not redesign PhyloLM around domain-matched genes. The paper faithfully runs the released method with
its released gene bank, fixed contract, and locked seed. A task-specific gene bank designed by the
authors would be a new adaptation with additional researcher discretion, not a faithful reproduction
of the baseline.

The rank-64 result also does not establish misapplication. Increasing LoRA rank does not guarantee
monotonically greater behavioral separation on PhyloLM's allele representation.

#### 7. MoTHer and Neural Phylogeny are not direct executable baselines

MoTHer and Neural Phylogeny infer relationships among observed checkpoints. This paper observes only
terminal leaves and estimates an unrooted phylogeny whose internal ancestors are latent. A direct
head-to-head would require changing either the observation model or the scientific problem.

Make this incompatibility explicit. An $\ell_2$ distance sensitivity may still be useful because MoTHer
uses $\ell_2$, but that is a metric ablation, not ``running MoTHer.''
